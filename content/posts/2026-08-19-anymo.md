## 阅读点评

这篇要解决的是贪心问题：一个模型吃文本、语音、音乐、轨迹，还要数据够大、模型能缩放。OmniHuMo（3.2M / 5000+h）是实在的工程贡献；R-FSQ + 并行掩码处理多流 token，集成合理。文本任务 111M→3B，FID 262→55.6，scaling 站得住。

但「any-modality」的核心实验偏浅：音频 FID 在 775M 后反弹，过拟合四个字不够；主结果几乎全在自建集上，HumanML3D 只做了 tokenizer / 建模策略消融，很难和 MDM、MoMask 横向比。组合条件展示了增益，却没讲轨迹如何改写语音驱动的动作。代码、权重、数据都没放。当作「大规模对齐数据 + 统一掩码生成器」的工程报告来读，比当作顶会方法论文更合适。

## 核心摘要

现有方法受限于固定模态和任务特定架构，跨模态交互和 multimodal scaling 几乎没人系统做，根因是缺大规模对齐数据。AnyMo 配套 **OmniHuMo**（3.2M 序列、5048 小时，文本全覆盖，约 500 小时语音或音乐对齐），用 **R-FSQ** 把动作打成多层残差 token，再用 **LLaMA 双向掩码 Transformer 并行预测所有流**，文本 / 语音 / 音乐 / 轨迹及其组合都能当条件。音视频对齐只有约 1/10，因此用三阶段课程训练。

## 方法概述和架构

{{< mermaid >}}
flowchart LR
  T[文本 T5-XL] --> M[并行掩码 Transformer\nLLaMA 111M–3B]
  A[语音/音乐 WavTokenizer] --> M
  R[轨迹 Conv] --> M
  M --> Q[R-FSQ 四流 token]
  Q --> X[3D 动作]
{{< /mermaid >}}

**R-FSQ。** VQ 易码本崩、单级丢细节。FSQ 用 sigmoid + round 做确定性标量量化；残差让第 0 流管全局，后面几流管细节。时间下采样 4，4 层、每层码本 2048。重建损失 \(\mathcal{L}_1=\|X-D(\sum_v \widehat Z^v)\|_2^2\)。

**并行掩码。** 同一时间步所有残差层一起换成 `<MASK>`，各流独立 embedding 再求和进 Transformer，各流独立 FFN 头。不把多流 flatten 成一条长序列。损失为各流交叉熵之和。

**条件编码器。** 文本 T5-XL，音频 WavTokenizer，轨迹轻量卷积，投影到同一 \(c\) 维。

**三阶段课程。**

1. 全部 text–motion 预训练，冻音频 / 轨迹编码器。
2. 引入音视频对齐子集，冻文本编码器和 Transformer，只训音频 / 轨迹编码器。
3. 联合微调：每 epoch 10% 纯文本 + 全部音频对齐，\(p=0.1\) 做模态增强。

## 核心创新点

1. **OmniHuMo：** 目前最大的多模态人体动作集之一；相对 BEAT / HumanML3D / MotionMillion，同时有文本、语音、音乐、RGB。
2. **R-FSQ tokenizer：** 残差 FSQ，避开 VQ 码本坍塌，分层补细节。
3. **AnyMo：** 并行掩码 + 模态专用编码器；111M→3B 验证 scaling（文本侧最干净）。

## 实验结果

数据集对照（论文 Table 1 节选）：

| 数据集 | 条数 | 时长 | 文本 | 语音 | 音乐 | RGB |
| --- | --- | --- | --- | --- | --- | --- |
| HumanML3D | 14.6K | 28.6h | ✓ | ✗ | ✗ | ✗ |
| MotionMillion | 2M | 2000h | ✓ | ✗ | ✗ | ✗ |
| **OmniHuMo** | **3.2M** | **5048h** | ✓ | ✓ | ✓ | ✓ |

重建 MPJPE (mm)：R-FSQ 在 HumanML3D / MotionMillion / OmniHuMo 上为 27.9 / 21.5 / 13.2，低于 ScaMo 与 GoToZero（训练数据不同，不完全公平）。数据从 0.05M→3M，HumanML3D 上 FID 160.7→17.3。

文本生成（OmniHuMo-Text）：

| 模型 | FID ↓ | R@1 ↑ |
| --- | --- | --- |
| 真实 | — | 0.74 |
| 111M | 262.10 | 0.63 |
| 775M | 148.81 | 0.71 |
| 1B | 102.21 | 0.74 |
| **3B** | **55.59** | **0.75** |

语音 / 音乐 FID 并不单调：775M 往往最好（Speech 83.80、Music 34.41），3B 反弹到 91.12 / 46.17。BAS 仍随规模缓慢上升。

组合条件（AnyMo-3B）：文本 + 轨迹使 FID 55.59→41.43，均误差 50.5→27.2 cm。语音 + 文本 + 轨迹 FID 91.12→76.55。音乐侧类似，Div 略降。实证覆盖主要是「文本+轨迹」「语音/音乐+文本+轨迹」，没有展示仅音乐+轨迹或语音+音乐。

建模策略（HumanML3D）：AR-Flatten FID 26.71，Mask-Flatten 20.89，**Mask-Parallel 19.46**。

## 细节

OmniHuMo 流水线：>2 亿网络视频 → PySceneDetect + TransNetV2 切场景并过滤 → YOLO / MOTRv2 / RTMW 做 2D → GVHMR 出 SMPL → Demucs 分人声/伴奏，BAS>0.15 标舞蹈，3D-Speaker + SyncNet + Whisper 标语音 → Qwen3-VL-32B 写描述。多数片段 2–10s。标注全自动，论文没有人工质检报告。

训练：tokenizer 16×H20，200 epoch，bs 256/卡；生成器 48×H20，210 epoch，bs 16/卡，AdamW，lr \(2\times10^{-4}\)→\(10^{-5}\)。

## 局限

- 主结果封闭在 OmniHuMo，缺少与 MDM / MotionDiffuse / MoMask 在标准基准上的全面对比。
- 音频 scaling 解释停留在「配对数据少 / 过拟合」，没有拆 WavTokenizer 瓶颈或文本预训练偏置。
- 组合条件缺机理分析；「任意组合」的实验覆盖不完整。
- 未开源；LLM 自动描述可能有偏差和风格单一。
- 作者也提到手指关节缺失、音视频对齐占比小。

## 阅读收获

1. **数据对齐先于统一模型。** 没有 500h 音视频对齐和三阶段课程，再大的 LLaMA 也只是多任务单输入。
2. **多流不要 flatten。** 残差层是层级结构；同一时间步一起 mask，比 AR-Flatten 质量和效率都好。
3. **Scaling 分模态看。** 文本数据够，FID 随参数单调降；音频配对少，775M 之后 FID 反弹。
4. **和本周 ARDY 对照。** ARDY 解决实时 + 长程运动学控制（root 显式留下）；AnyMo 解决任意模态组合 + 规模（全身离散成多层 token）。都用了 FSQ，拆分的自由度完全不同。
