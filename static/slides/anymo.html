01 挑战

缺大规模模态对齐数据；现有方法多任务但单输入，吃不下任意组合。

02 Idea

先把数据集做大做齐，再用 R-FSQ 多层 token + 并行掩码一次预测所有流。

03 方法

OmniHuMo 流水线、R-FSQ、模态编码器、三阶段课程。下文用图和代码展开。

04 结果

文本任务明显随规模变好；音频 FID 在 775M 后波动；组合条件能再压误差。

问题

不是缺生成器，是缺「对齐」和「组合」

  • 文本、音乐、语音、轨迹各自都有不错的单模态方法。
  • 多数「统一框架」其实是一个 backbone 挂多个单模态任务，不能对同一段动作同时吃多种条件。
  • 跨模态交互和 multimodal scaling law 几乎没人系统做过，根因是对齐数据太少。

核心 Idea

多层残差 token 并行 mask，而不是 flatten 再自回归

FSQ 比 VQ 稳，但单级仍丢细节。R-FSQ 让第 0 流管全局，后面几流管残差，重建误差逐级降。

多流若拼成一条长序列再 AR，时间和层级都乱。AnyMo 在同一时间步把所有层一起 mask、一起预测。

贡献

三条：数据、分词、可缩放生成器

C1 · OmniHuMo

3.2M / 5048h，文本全覆盖，~500h 语音或音乐对齐，带 RGB。作者称是目前最大的文本–音频–视觉一体动作集。

C2 · R-FSQ

4 层残差 FSQ，每层码本 2048，时间下采样 4。HumanML3D 重建 MPJPE 27.9 mm，优于 ScaMo / GoToZero。

C3 · AnyMo + scaling

LLaMA 双向掩码，111M→3B。文本 FID 262→55.6；任意组合靠模态编码器和三阶段课程，不靠测试时优化。

方法 · R-FSQ

确定性标量量化 + 残差，替代最近邻 VQ

  • VQ 两个病：不可微最近邻 → 码本崩；单级压缩 → 细节没了。
  • FSQ：sigmoid 把每维限制住，再 round 到 Li 档。码本大小是各维档数的乘积，不靠学习 codebook。
  • 残差：R⁰=Z，每层量化残差。m⁰ 管全局，高层管动态细节。
  • 实现：4 层、每层 2048、↓4，Enc/Dec 跟 SnapMoGen。16×H20，200 epoch，bs 256/卡，lr 2e-4。
# 论文 Eq.1, Eq.3
hat_z_i = round(sigmoid(z_i) * (L_i - 1))
|C| = prod(L)                      # 双射展平

L1 = ||X - D(sum_v FSQ(R^v))||^2   # 只重建，无对抗

消融：HumanML3D 上训 tokenizer，数据从 0.05M→3M，FID 160.7→17.3，MPJPE 94.6→27.9。规模几乎就是重建质量。

方法 · 并行掩码

同一时间步，所有残差层一起盖、一起猜

def parallel_mask_step(tokens, cond):
    # tokens[v]: 第 v 层离散序列，长度 t
    idx = sample_timesteps()                 # 所有层共用
    masked = [replace(tokens[v], idx, MASK) for v in streams]
    Z_enc = sum(Embd[v](masked[v]) for v)
    h = llama_bidirectional(Z_enc, cond)     # text/audio/traj
    logits = [FFN[v](h) for v]
    L2 = -sum(CE(logits[v], tokens[v]) for v)
    return L2

条件：T5-XL 文本、WavTokenizer 音频、轻量卷积轨迹，都投到同一 c 维。HumanML3D 上建模策略消融：AR-Flatten FID 26.71 · Mask-Flatten 20.89 · Mask-Parallel 19.46。并行不只更快，质量也最好。

讨论

局限：评测封闭、开源空、音频曲线没讲透

评测封闭

主结果几乎全在 OmniHuMo。HumanML3D 只做了 tokenizer / 建模策略消融，没有和 MDM、MotionDiffuse、MoMask 等生成 SOTA 全面对比。

未开源

代码、权重、数据集都没放。附录 C 超参很全，但没有数据就无法复现。自动标注（尤其 LLM 描述）也没有人工质检。

any-modality 偏工程

组合增益展示了，但没解释轨迹如何改写语音驱动的动作，文本和 ASR 是冗余还是互补。手指关节缺失，纯运动学。

带走

和本周 ARDY 对照着看

1 · 数据对齐先于统一模型

AnyMo 能做组合条件，先决条件是 500h 音视频对齐 + 三阶段课程。没有对齐数据，再大的 LLaMA 也只是多任务单输入。

2 · 多流不要 flatten

残差层是层级结构，不是更长的一维序列。同一时间步一起 mask，比 AR-Flatten 质量和效率都好。

3 · Scaling 分模态看

文本数据够，FID 随参数单调降。音频配对少，775M 之后 FID 反弹。不要把文本曲线直接外推到语音/音乐。

4 · 对工作的启发

ARDY 解决的是实时 + 长程运动学控制；AnyMo 解决的是任意模态组合 + 规模。一个偏交互系统，一个偏数据与统一生成器。两者都用了 FSQ，但 ARDY 把 root 显式留下，AnyMo 把全身都离散成多层 token。
