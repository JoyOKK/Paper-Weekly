问题

交互场景要「改条件立刻出下一段动作」

动画、游戏、仿真、人形机器人都要在运行时生成 3D 人体动作，并且立刻响应新的文本或空间指令。论文把方法分成两类：

  • 离线：整段并行去噪 / 掩码补全。文本和关键帧很强，但改一句 prompt 就要重跑全序列。
  • 在线：自回归短窗生成。跟手，但历史一短，复杂语义和 10 秒后的路点就会丢。

图 3 · 离线一次出全片；在线只出当前窗，但条件可以看很远。

核心 Idea

好控的量显式留着，好学的量压进 latent

图 4 · Hybrid 表征。全局 root 留在场景坐标；身体进 latent，每个 token 覆盖 P=4 帧。

空间约束几乎都定义在全局场景坐标里。局部速度表征一积分就漂，无法直接覆盖。

少步扩散（4–10 step）吃不下高维显式身体。Tokenizer 把 body 压紧后，生成才学得动。

# 论文 Eq.1–2
m_root = (p, cosψ, sinψ)          # R^5
m_body = (θ, J, J_dot, c)         # 随关节膨胀
x      = (m_root, x_body)         # hybrid
x_body = TokenizerEnc(m_body)     # R^L
贡献

三条贡献，分别对应表征 / 生成器 / 验证

C1 · Hybrid 表征

latent body + 全局显式 root。轨迹可直接覆盖，身体在紧凑空间生成。避免局部速度积分的累积误差。

C2 · 两阶段 AR 扩散

可变历史最长 8s，未来约束最长 10s。原生支持路径、路点、全身关键帧、稀疏关节位置 / 旋转。不挂优化器，不挂 RL。

C3 · 大规模验证

Bones Rigplay ≈ 700h 做消融；HumanML3D 对比 MaskControl / DiP。交互 demo：动态文本、路径跟随、键鼠 locomotion。

约束种类（论文 Fig.6）：dense root trajectory · sparse waypoints · full-body keyframes · sparse joint pos / rot。

方法 · 总览

训练与推理的两段流水线

图 5 · 方法流程图。Tokenizer 只重建身体；扩散在 hybrid token 上生成；运行时只滚动当前 2s 窗口。

方法 · Tokenizer

因果 AE + FSQ，解码时把 root 转成本地速度

  • Enc / Dec 各 8 层因果 Transformer，latent 512。输入按 P 帧 reshape 成 token。
  • Hybrid token：x^{1:T} = [m_root^{1:T}; x_body^{1:T}]，D = L + 5P。
  • 解码器条件用本地 root (ψ̇, ṗ_x, ṗ_z, p_y)。全局 root 适合控制，本地速度适合抑制滑步。
  • 默认 FSQ 64 级 × 128 维。Vanilla AE 在 40 帧 horizon 上会训崩。
def tokenize(m_root, m_body, P=4):
    patches = rearrange(m_body, "n d -> (n/P) (P d)")
    x_body  = FSQ(encoder(patches))          # 因果注意力
    root_p  = rearrange(m_root, "n 5 -> (n/P) (P 5)")
    return concat([root_p, x_body], dim=-1)

def decode(x):
    root_local = global_to_local(x.root)     # 防滑步
    return decoder(concat([root_local, x.body]))
Tokenizer稳定性选用
Vanilla AE长 horizon 发散公开集实验
VAE 128D可用消融对照
FSQ 64-128最稳默认 / demo

训练：重建 + skate loss（权 0.01），4M step，AdamAtan2，lr 2e-5，单卡 A100。Patch=1 后期不稳；Patch=8 FID 略好但约束精度掉。

反例：「向前走，再弯腰捡东西，再继续走」。若历史只有最近走路帧，模型不知道捡东西做过没有，会漏做或重复做。这就是 DiP / DartControl 短上下文的病。

方法 · 去噪器

交错两阶段：先干净 root，再条件出 body

图 7 · 论文 Fig.3。假设：先有干净轨迹再生成身体，比两者一起预测更容易同时满足文本和约束。

方法 · 去噪循环

推理时的交错去噪（对应 Fig.3 右）

def denoise_window(s, history, goals, K=4):
    x = randn(C, D)                          # noisy hybrid
    for k in reversed(range(K)):
        x.root = overwrite(x.root, goals)    # 精确轨迹
        m_root = root_tf(k, s, history, x, goals)
        x_body = body_tf(k, s, history, x,
                         detach(m_root), goals)
        x0 = concat([m_root, x_body])
        x  = q_sample(x0, k - 1) if k else x0
    motion = tokenizer.decode(x0)
    return unpatchify(motion)                # G = C·P 帧

两支路都是 8 层 × 8 头 × 1024 维，部署模型约 156M。文本用 LLM2Vec（Llama-3-8B-Instruct 上训的 embedding）。

不用 dropout：会把 root 覆盖条件随机关掉，轨迹控制会坏。

单阶段对照：路点误差 0.024 → 0.164 m。文本 R-prec 几乎不动，说明两阶段主要买的是控制精度，不是语义。

方法 · 训练

四项损失，约束从 GT 动作上采样

L = L_hybrid + L_dec + L_goal + L_consist

L_hybrid  = smooth_L1(x0_hat, x0)                 # token 空间
L_dec     = smooth_L1(decode(x0_hat), m_body)     # 解码后身体
L_goal    = smooth_L1(v * (m0_hat - g))           # 只罚被钉住的维
L_consist = ||J_hat - FK(θ_hat)||_2               # 位置 vs 旋转

采样窗

最长 10s 片段上随机切 G 帧窗，于是每条样本的 H、F 都在变。绕 y 轴随机旋转。

约束集合

2D root 关键帧 / 轨迹、全身稀疏或成块关键帧、末端执行器、脚接触。文本与约束各 10% dropout → CFG。

优化

DDPM 默认 10 step，交互可用 4。AdamAtan2，lr 2e-5，bs 512 × 4×A100，1M step。

系统

延迟感知重规划：把推理藏进正在播的 buffer

图 8 · 论文 Fig.5。root 先平移到原点再预测，再加回场景坐标。历史与窗外目标用截断滑窗，训练见过的最长上下文是 8s。

4-step

RTX 4090 平均 33 ms，无需 buffer，20 fps 生成窗 40 帧。

10-step

63 ms，控制更准，用 1 帧 buffer 把延迟藏起来。

键鼠

鼠标路点插值平滑成轨迹；键盘速度积分出 root 轨迹再喂模型。

讨论

局限：记忆、步数、物理都还没合进去

扁平历史

过去帧整段喂进 Transformer。超长任务不经济。作者点名结构化记忆 / 更新机制。

仍是多步扩散

4-step 已可用，但还能叠 shortcut / consistency。延迟和步数还是绑在一起。

纯运动学

没有动力学。滑步、抖动仍在。下一步想统一预测运动学 + 动力学，服务物理关键场景。

Bones 是私有棚拍数据，公开复现会落在 HumanML3D 那套 vanilla AE 设定上，和 demo 的 FSQ 700h 模型不是同一个。

带走

四条可以写进自己系统的判断

1 · 先问谁必须 overwrite

全局轨迹、必须钉死的关节，显式留着并允许覆盖。其余高维身体进 tokenizer。全显式少步扩散学不动，全隐式又盖不了场景坐标约束。

2 · 控制写进训练，别后挂

从 GT 采样约束当条件，比测试时优化 / 再训 RL 更适合交互。窗口外目标当成额外 token，比把生成窗拉到 10s 便宜。

3 · 短生成、长条件

生成窗保持 2s 保证跟手；历史 8s 扛复杂语义；未来 10s 扛长程路点。质量和反应速度用 horizon 做对换（40 vs 8）。

4 · 两阶段买的是控制

消融里 R-prec 几乎不涨，路点误差差一个数量级。先出干净 root 再出 body，是「又要文本又要钉点」时的结构假设。
